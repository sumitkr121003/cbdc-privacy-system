## Measurement boundaries

- Wall clock: time.perf_counter_ns elapsed seconds.
- Process CPU: time.process_time_ns elapsed process CPU seconds.
- Whole-system CPU utilization: Windows GetSystemTimes counter delta: (kernel + user - idle) / (kernel + user) * 100; None on unsupported platforms or failed/invalid reads.
- Process CPU capacity share: process CPU seconds / (wall seconds * logical CPU count) * 100; average process share of logical processor capacity, not whole-system CPU utilization; may be unavailable.
- Peak traced memory: tracemalloc peak bytes above the per-execution starting allocation baseline.
- Timing: Workload generation, wallet creation, signing, funding, integrity checks, outcome comparison, and report writing are excluded. Sequential timing covers transfer_signed calls; parallel timing covers process_batch including executor setup, validation, commits, and shutdown.
- Instrumentation: tracemalloc runs during both timed execution paths; its instrumentation overhead is included consistently.
- Latency: Per-transfer latency samples are reported for sequential execution. Parallel percentiles use batch-submission-to-final-outcome timestamps recorded at final result creation.
- Parallel latency: Parallel latency is measured from the timestamp immediately before process_batch submission to each transaction's final success, conflict, or rejection result. It includes validation queue waiting time.
- Completion timestamp instrumentation: Optional completion timestamp and dict-recording cost capture is enabled for benchmark runs. Its measured estimate includes the second clock read used for the estimate; the estimate itself adds a small amount of overhead and is included in timed execution.
- Whole-system CPU limitations: Other system processes contribute to this system-wide average. Short execution intervals limit precision; unavailable reads are reported as null. Counter snapshots bracket each measured run.
